# 听序 · Tingxu

**把录音变成文字，再把文字整理成有用的记录。**

## 一、这个项目能做什么？

听序是一个在电脑上运行、通过浏览器操作的录音整理工具。你可以把它理解成一张工作台：先放入录音，再转成文字，最后整理出会议纪要、重点和待办事项。不会编程也可以按照下面的步骤部署和使用。

它适合整理会议、访谈、课程和个人语音记录。你既可以连接 **QS668 开放协议录音卡**，也可以直接导入电脑上已有的音频，不必为了使用它额外购买设备。

| 你想做的事 | 听序提供的功能 |
| --- | --- |
| 把录音拿到电脑上 | Type-C 采集、蓝牙导入、本地音频上传 |
| 管理已经保存的录音 | 搜索、筛选、试听、下载、改标题，以及可恢复的回收站 |
| 不再逐句听录音 | 在本地转写，或使用自己配置的云端转写服务 |
| 快速了解一段录音 | 阅读完整转写、生成智能纪要、提取重点与待办，导出 Markdown 文件 |
| 知道处理到哪一步 | 查看采集、转写、总结阶段、完成文件数及日志 |
| 区分是谁在说话 | 给录音中的说话人命名；登记本地声纹样本，获取匹配建议后人工确认 |
| 减少专业词汇错误 | 自定义热词、权重、分组和字面纠错规则 |
| 按自己的需求总结 | 选择模型服务，编写自己的总结提示词 |
| 把纪要分享到飞书 | 手动上传或总结后自动上传，保存文档地址，点击“飞书云文档”入口打开 |

日常使用顺序：

```text
导入或采集录音 → 转写成文字 → 确认人物（可选） → 生成纪要 → 阅读或导出 → 上传飞书（可选）
```

蓝牙操作会在“录音卡”页面原地等待。扫描到一台设备后尝试连接；发现多台设备时先选择。成功连接并读取文件后进入卡上文件管理，失败则弹出原因和操作建议，不再自动跳到任务中心。设备操作按需连接，不代表浏览器一直保持蓝牙连接。

界面支持手机、平板和电脑屏幕：手机用底部导航与列表/详情切换，平板根据宽度调整，电脑用双栏阅读。**默认部署只允许在运行服务的电脑上访问**，并不会自动让另一台手机或平板连上电脑，详见第三部分。

当前是早期版本，主要面向 macOS。页面视觉效果、真实蓝牙传输及声纹准确率仍需在实际设备上验证。本 README 暂未放入未经验证的页面截图。

## 二、如何部署？

下面以 **Mac 电脑**为例。命令在“终端”中执行：可以按 `Command + 空格`，搜索“终端”并打开。每次复制一个代码块，执行结束后再继续。

### 第一步：准备工具

需要安装：

- **Python 3.11–3.13**：运行本项目，推荐 Python 3.12。
- **FFmpeg**：把不同格式的录音转换成模型能处理的音频。
- **Git**：从 GitHub 下载项目。基础录音流程不依赖 Node.js；可选飞书上传功能通过 npm 安装 CLI 时需要 Node.js/npm。

下面的安装命令需要电脑已安装 Homebrew。若提示 `brew: command not found`，先按 Homebrew 官方安装说明安装，再重新打开终端。

```bash
brew install python@3.12 ffmpeg git
```

### 第二步：下载项目并建立运行环境

```bash
git clone https://github.com/happynailinzz/tingxu.git
cd tingxu
python3.12 -m venv funasr-env
source funasr-env/bin/activate
python -m pip install --upgrade pip
```

`funasr-env` 是这个项目专用的 Python 环境，用来安装依赖，减少与电脑上其他软件互相影响的机会。以后重新打开终端，需要先 `cd` 到项目目录，再执行 `source funasr-env/bin/activate`。

### 第三步：安装依赖

**需要本地转写和声纹功能**，执行完整安装：

```bash
python -m pip install -r requirements.txt
```

下载量较大，请等待命令完成。PyTorch 与 torchaudio 需要相互兼容；如果提示没有适合的安装包，先检查 Python 版本和电脑架构。

**只需要管理录音、蓝牙导入及云端模型**，可以先安装基础依赖：

```bash
python -m pip install -r requirements-core.txt
```

基础安装不包含本地识别模型所需的完整依赖。以后需要本地转写或声纹时，再执行完整安装命令。

### 第四步：启动并打开页面

```bash
python qs668-console.py
```

终端会显示管理台地址，通常是：

```text
http://127.0.0.1:8765
```

把地址复制到电脑浏览器中打开。如果默认端口被占用，程序会尝试后续端口，**以终端实际显示的地址为准**。运行期间保留终端，按 `Ctrl+C` 可以停止服务。

### 第五步：导入第一条录音

- **已有音频**：在“录音档案”中点击“导入音频”，选择文件。
- **Type-C 录音卡**：插卡后进入“录音卡”页，选择文件采集；完成后先安全弹出再拔线。
- **蓝牙录音卡**：打开设备蓝牙，在“录音卡 → 蓝牙导入”中扫描或连接，等待当前页显示文件，再选择导入。首次使用可能需要允许启动管理台的应用访问蓝牙。

支持 WAV、Opus、OGG、MP3、M4A、FLAC、AAC、WebM、MP4。本地上传每个文件最多 1 GB；同名录音不会直接覆盖。裸 Opus 可能需要转写时转换成 WAV 后才能播放。

### 第六步：配置模型并开始处理

进入“模型与提示词”：

1. **转写**：选择本地 Paraformer / SenseVoice，或填写兼容文件转写接口的云端服务。
2. **总结**：新用户请选择自定义服务，填写服务商提供的基础地址、模型名称与 API Key。
3. **提示词**：留空使用默认纪要模板；也可以填写自己的要求，例如：“按背景、结论、分歧、行动项整理，不补充原文未提及的内容。”
4. 保存后，回到录音档案，选中音频，执行转写、总结或一键处理。

云端服务的基础地址一般填写到 `/v1`，不要填写完整的 `/chat/completions` 路径。模型名称必须是服务商实际支持的名称。

```text
基础地址示例：https://api.example.com/v1
模型名称示例：your-model-name
API Key：填写你自己的密钥，不要发到公开仓库
```

保存设置不会请求模型；真正处理时才调用。模型和提示词修改后对新任务生效，正在运行的任务保留原设置。

### 可选：上传纪要到飞书

本地总结完成后，可以将纪要 Markdown 转成飞书云文档。只上传纪要正文，开头的模型、文件名和校验指纹等元数据会自动移除；本地 Markdown 保留完整处理记录，音频不会随纪要上传。

先安装 Node.js/npm，再安装飞书官方 CLI，并按提示完成应用配置和浏览器授权：

```bash
brew install node
npx @larksuite/cli@latest install
lark-cli config init
lark-cli auth login --domain docs --domain drive
lark-cli auth status --json --verify
command -v lark-cli
```

在“模型与提示词 → 飞书文档”启用上传，将最后一条命令输出的完整路径填入 CLI 设置。选择“完整工作流总结后自动上传”，可在一键处理完成总结后接着发布；也可以在录音详情页点击“上传飞书”，单独上传已有纪要。

上传成功后，按钮变为“飞书云文档”图片入口，点击在新窗口打开文档。链接保存在本机，刷新页面、重启服务或修改录音标题后仍可使用。任务中心同时显示上传阶段、执行结果和文档链接。桌面操作栏统一按钮尺寸，手机使用两列布局。

注意：

- 功能默认关闭；启用自动上传后，新的完整处理任务会把纪要正文发送到飞书。
- 创建文档链接不会自动开放访问权限；对方能否查看，取决于飞书文档的分享设置。
- 每次点击上传会创建新文档；当前不自动覆盖旧文档。旧版本未保存的历史上传地址不会自动恢复。
- 后台服务已兼容 npm CLI 的 Node 路径。如果后台仍报告 Keychain 或授权错误，请在正常终端检查 `lark-cli auth status --json --verify` 并查看任务日志，不要把密钥或令牌发到公开仓库。
- 更新后端代码后需重启管理台；只有样式和图片调整时，刷新页面即可。

### 可选：登录后自动启动

手动运行确认正常后，可以让 macOS 在登录后启动管理台。先按 `Ctrl+C` 停止手动进程，再在项目目录执行：

```bash
python scripts/console-service.py install
```

以后更新代码需要重新加载服务：

```bash
python scripts/console-service.py restart
```

取消自动启动：

```bash
python scripts/console-service.py uninstall
```

更多维护步骤见 [CONSOLE-SERVICE.md](CONSOLE-SERVICE.md)。

## 三、部署与使用时要注意什么？

### 本地处理与云端处理不同

- 本地转写与声纹推理在电脑上执行；第一次使用可能从网上下载模型，之后才能离线使用。模型需要额外磁盘空间、内存和运行时间。
- 云端转写会上传你选中的音频；总结服务接收转写文字。请在使用前确认这些内容适合交给所配置的服务。
- 云端服务可能收费，需要你自行开通并配置，项目不会附送模型额度。云端转写在工作台中限单文件 100 MB，服务商可能有更低限制。

### “手机适配”不等于“手机已经可以访问”

默认仅监听 `127.0.0.1`，只有本机浏览器能访问。另一台手机或平板无法通过它访问电脑。项目目前没有提供面向公网的登录验证和部署方案，不建议直接把服务端口暴露到互联网。

### 蓝牙连接失败时

先阅读当前页弹窗中的原因和建议：

- 检查电脑蓝牙、录音卡电源，以及 macOS 的蓝牙访问权限。
- 断开手机应用或其他软件占用的设备连接；必要时安全弹出 Type-C 并拔线后再试。
- 转写与蓝牙可以使用不同 Python。程序会检测已安装 `bleak` 的环境，也支持通过 `QS668_BLE_PYTHON` 显式指定；缺少依赖时在对应环境安装 `requirements-core.txt`。
- `BLE is unsupported` 表示当前进程无法使用系统 BLE 控制器，不能据此判断录音卡不兼容。可以从本机终端启动管理台排除受限启动环境。

蓝牙通常比有线传输慢，导入文件与实时音频采集不能同时运行。连接验证成功后也可能因设备休眠、距离或其他连接而失效，后续操作会按需重新连接。

### 声纹与热词需要人工校对

声纹登记请选择 **3–30 秒清晰、没有其他人插话**的音频，每人最多 5 个样本。相似度只是候选参考，不是身份认证；确认关联后用于阅读及后续总结，不自动改写已有纪要。

旧转写没有精确分段时，可以手动命名；要生成声纹建议，需要用新版支持说话人分离的模型重新转写。重新转写可能改变说话人编号，所以旧关联不会自动套用。

热词偏置取决于模型能力，SenseVoice 和当前云端转写路径不使用热词偏置。字面纠错会直接替换文字，使用前请检查规则，避免误改原意。纪要也应与原录音核对，尤其是人名、金额、时间和待办责任人。

### 数据保存在电脑上，请做好备份

| 本机位置 | 保存的内容 |
| --- | --- |
| `nextproto/archive/audio/` | 音频 |
| `nextproto/archive/corpus/` | 转写文字 |
| `nextproto/archive/brief/` | 纪要 |
| `sessions/` | 会话分段、人物关联与处理记录 |
| `.voiceprints/` | 声纹参考音频与本地备份 |
| `.tingxu-people.json` | 人物和声纹向量 |
| `.tingxu-vocabulary.json` | 自定义词库 |
| `.qs668-web-settings.json` | 模型配置、密钥及飞书上传选项 |
| `.qs668-library.json` | 显示标题及已上传的飞书文档地址 |

这些数据已加入 Git 忽略规则，**不要手动把它们上传到公开仓库**。密钥配置文件使用本机 `0600` 权限；页面只显示是否已保存密钥，不回传密钥内容。回收站支持恢复本地档案，卡上原件保持只读。

任务列表保存在当前服务内存中，重启后会清空；音频和处理结果保存在磁盘。处理过程中不要停止服务或拔线。进度按阶段和完成文件数显示，模型没有内部进度时只显示等待动画，不代表逐秒识别进度。
